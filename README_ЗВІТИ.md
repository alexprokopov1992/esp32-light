# PowerPinger: добові звіти о 00:02 + завершений тиждень

Оновлено **дві частини** з наданих файлів `esp32-light(3).zip` і `Code.gs`.

## Графік роботи (Europe/Kyiv)

- Щоденно після **00:02** ESP32 запитує звіт **за попередню повністю завершену календарну добу**.
- Запит у понеділок о 00:02 має звітну дату **неділя** та формує **весь попередній тиждень**, понеділок 00:00 — наступний понеділок 00:00.
- Інші дні: збережений тижневий графік від понеділка до кінця відповідної звітної дати; майбутні дні тижня на графіку білі. У підписі є суми за цей період та окремо ON/OFF/UNK за завершену добу.
- Пропущені **звіти** після відновлення інтернету: послідовно надсилаються за кожну ще не підтверджену дату, не частіше ніж раз на 15 секунд. Невдалий запит повторюється через 10 хвилин. Прогрес зберігається в NVS (`cfg/rpt_done`).
- Під час **першого** запуску нової прошивки звіти починаються зі вчорашньої дати. Старі `wrep_day`/`wrep_final` не використовуються, адже вони відповідали неповним добам; автоматичного перерахунку більш старої історії при оновленні немає.
- Google Apps Script зберігає ідентифікатори **180 останніх відправлених звітних дат** у `POWER_REPORT_SENT_DAYS_V1`. Повтор того самого запиту повертає `already sent YYYYMMDD` без другого Telegram-повідомлення.

## Встановлення: порядок обов'язковий

1. **Спочатку Google Apps Script.** У проєкті Apps Script замінити весь код файлу `Code.gs` на доданий у пакеті `Code.gs`.
2. Переконатися у **Project Settings → Time zone: (GMT+02:00) Eastern European Time — Kyiv / `Europe/Kyiv`**. Якщо часова зона проєкту неправильна, скрипт навмисно відхиляє звіт замість тихого зміщення меж доби. Для однакового відображення таблиці також бажано встановити часовий пояс Google Spreadsheet `Europe/Kyiv`.
3. Переконатися, що Script Properties містять `GS_SECRET`, `TG_TOKEN`, `TG_CHAT_ID` і що `CFG.DEVICE_FILTER` (`pinger`) відповідає `dev_id` ESP32.
4. У Apps Script **Deploy → Manage deployments → Edit (поточне розгортання) → Version: New version → Deploy**. Саме оновити наявний `/exec`, щоб URL в NVS ESP32 не змінився.
5. Тільки після цього зібрати/прошити оновлений ZIP як ESP-IDF-проєкт (звичайний `idf.py build`, `idf.py -p COMx flash monitor`). **Не виконувати erase_flash**, якщо потрібно зберегти Wi-Fi, Telegram, Google URL/secret та NVS-журнал.
6. Через лог монітора перевірити `Completed-day reports`, `Requesting completed-day report YYYYMMDD` і `response-confirmed=yes`. Після підтвердження з'явиться NVS `rpt_done`.

Виклик для ручної перевірки (надішле повідомлення в Telegram лише один раз для цієї дати):

`GET https://script.google.com/macros/s/<DEPLOY_ID>/exec?action=weekly_report&date=2026-11-11&secret=<GS_SECRET>`

Якщо дата пропущена, для старих клієнтів використовується **попередній завершений день**; `action=weekly_report` залишено для сумісності. Секрет не варто публікувати в логах або пересилати іншим.

## Межі гарантій

- Скрипт не вигадує записи: якщо ESP32 не зберегла/не відправила подію ON/OFF, відповідний історичний стан може бути невідомим або неточним. Надолуження звітів **не відновлює втрачені події**.
- Відправлення повідомлення в Telegram і запис прапорця в Properties не є однією транзакцією. Рідкісна помилка після реального надсилання, але до запису прапорця, може дати дубль. Загалом повтори після тайм-ауту дедуплікуються.
- У дні переходу на літній або зимовий час фактична тривалість доби в Києві може бути 23 або 25 годин. Текстова статистика рахує реальні секунди; графічна шкала, як раніше, показує локальні години 0–24, тож повторну осінню годину не відображає окремо.
- Якщо пізніше прийдуть логи зі старими `ts`, раніше надісланий звіт автоматично не перераховується. Для повторного ручного запуску необхідно окремо зняти позначку цієї дати у Script Property `POWER_REPORT_SENT_DAYS_V1`.

## Перевірки без реальної ESP32 / Telegram

`TZ=Europe/Kyiv node tests/test_apps_script.js`

`gcc -Wall -Wextra -Werror -std=c11 -O2 tests/test_report_calendar.c -o /tmp/report_calendar_test && /tmp/report_calendar_test`

Ці тести перевіряють розрахунки дат, добових/тижневих інтервалів, повторні виклики, помилку Telegram, невідомі періоди, календарні межі та DST. Повна компіляція ESP-IDF, реальний POST/GET, Telegram і прошивання пристрою в цьому середовищі **не запускались**.
